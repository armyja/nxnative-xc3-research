## 4. Reading the img-final fields

The printed `fmt`, dimensions, `type` and `usage` are the **Metal** properties of the texture that was shipped
(`t.pixelFormat`, `t.width/height/depth`, `t.textureType`, `t.usage`); `rid` is that texture's resolved id, `tid` the
texture-table index, `ser` the registered serial.

- `actual=real`: the encoding shipped a real texture, not the dummy.
- `usage_blocked=0`: the shader-write usage check did not clear it.
- `reg0 aid2`: runtime image register 0, argument id 2 (the shader's `fp_i_cb2_48_r32ui`, `texture2d<uint>`).
- `tid7616`, `ser=13053`, `rid=0x359`, Metal format **53 = R32Uint**, **640×360×1**, `type=2` (2D), `usage=0x7`
  (shader read | shader write | render target).

What this establishes: the target draw's encoding path, after the PSO succeeded, **selected a real R32Uint 640×360 2D
texture** for the image binding in the same pass and the same draw. It does not establish GPU submission or execution, any
image read or write value, or pixel correctness. `tid`, `ser` and `rid` are three different things and none of them alone
means "the same object as some other run"; serials across runs are not comparable, and this run's `ser=13053` must not be
matched against the earlier `12774` or `12890`.
