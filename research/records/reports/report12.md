## Test gap restored
`a6acb22` rewrote the fixtures and lost the real two-Slct case. `build_slcts()` now writes genuinely separate
Slcts: each body is self-contained (its program table and NVSD offsets are relative to its own start) and is
placed at its own `slct_section` offset, with its own gapped `xv4` / `unk` windows. The new test puts Slct 1 at
a non-zero offset, asserts its window bases (0x300 / 0x1200), and asserts the code and control bytes each of
its stages receives, with all four stages carrying distinct content — a parser using the section base for the
NVSD would read Slct 0's body. The multi-program tests are kept: different base level, not a substitute.
All earlier refusals stay (version, section bound, prefix break, control length, half stage, truncation).

## Pairing
`spch_programs(found)` regroups by identity and `spch_pairs(found)` returns a pair only for exactly `[vs, ps]`.
Identity is parsed from the label `spch.py` writes and **validated against the label grammar**, using the last
`#SPCH#` so a source name containing the marker still resolves; a foreign label is not a program. A repeated
stage in one program is refused (`red`), never collapsed into a pair. `pairs_of()` = `var_pairs() | spch_pairs()`
and it is what every `scan_file` return and the `main` path now call, so there is no uncalled helper. BNSH /
Unity `#var` behaviour is untouched. No `#var` label is fabricated, `shader_separable` stays off, and a lone
vertex program gets no invented pixel partner.

**Verdict: geometry is unsupported and silently non-executing downstream** — the shader object exists in
`NvProg::sh[2]` but no encoder path consumes it, and Metal has no geometry stage. This is why the six geometry
chains are left unpaired rather than reduced to their vertex and pixel ends. `STAGE_NAME` merely naming
`geometry` is not backend support.
