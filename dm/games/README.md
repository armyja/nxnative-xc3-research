# Game profiles

Each game the port knows has a folder `dm/games/<id>/`, named after the base game's title ID: Mario's is `010015100B514000`, Engage's `0100A6301214E000`. The folder holds:

- **`game.tsv`**: the game's constants, one `key<TAB>value` row each, with comments on their own lines.
- **The shader tables** that `shader_split.py` writes: `shader_map.tsv` (+ `.conflicts.tsv`), `shader_facts.tsv`, `shader_pairs.tsv`.
- **`shader_facts_manual.tsv`** (optional): hand-written translation facts in `shader_facts.tsv`'s row format, for what the machine code cannot tell (Link's Awakening: a vertex input the integer-input guess gets wrong). `shader_split.py` merges it over the generated rows; since the table is on the chain, changing it changes only that profile's chain version.
- **`c1_full.tsv`**: regenerated by `c1_guard.py` after each shader build.
- **`pso_manifest.tsv`**: the prewarm seed list.
- **`vk_capture.tsv`** (Vulkan games with `shader_vk_capture`): the keys of the SPIR-V modules the game generates at run time.
- **`bf_want.tsv`**.
- **`dmsh_chain.h`**: the chain version, written by `dmsh_chain.py --header`.

Everything game-specific belongs here. Code reads the profile; it does not hard-code a game.

| Who | Picks the profile with | Reads |
|---|---|---|
| Shader tools (`shader_split.py`, `dmsh_chain.py`, `dmsh_build.py`, `dmsh_facts.py`) | `DM_GAME=<id>` | tables, `nvn_*`, `shader_*` keys |
| Host (`make -C dm/host`, `dm/gfx/tests`) | `GAME=<id>` | `gen/<id>/game_profile.h`, generated from `game.tsv` by `game.py header` |
| `dm/ios/tools/build_ipa.sh` | `GAME=<id>` | app name, bundle ID, IPA name, modules, RomFS marker, tables |
| `scripts/build_ipa_from_nsp.py` | the NSPs' title ID | everything above. With no matching profile it writes a survey, then a provisional profile outside the repository and a best-effort IPA (`--survey-only` stops after the survey) |

None of them has a default game: without one they stop and list the profiles. To query a profile:
- `python3 dm/games/game.py list` lists the profiles.
- `python3 dm/games/game.py <id> <key>` prints one key.

## Keys

| Key | Meaning |
|---|---|
| `title_id`, `program_id` | Identity. `program_id` is what `svcGetInfo(ProgramId)` reports. The game's name is not stored: the NSP script reads it from the NSP's control data (NACP) |
| `name` | The game's name, only a label for `game.py list`, error messages and the Mac window title. The iOS app's name is the game name in the base NSP's control data and its bundle ID is `org.nxnative.<title ID in lowercase>`; the NSP script's `APP_NAME` / `BUNDLE_ID` and `build_ipa.sh`'s `DM_DISPLAY_NAME` / `DM_BUNDLE_ID` override them |
| `ipa`, `app_category` | iOS app: the default IPA file name and the App Store category |
| `build <ver> <display version> <module>=<build ID>…` | One row per known version. The NSP script rejects other builds. The host reports the display version by `main`'s build ID |
| `package` | Version packed into the IPA by default |
| `shader_versions` | Versions whose union the shader tables are (base game first). All of them are needed to build |
| `modules` | Code modules rewritten and loaded, in load order. `rtld` is replaced by the host |
| `romfs_marker` | A path that must exist in the RomFS |
| `zip_store` | Extensions the IPA stores without compressing |
| `graphics` | `nvn` (the default) or `vulkan`: the game renders with Vulkan and the host implements its `vk*` imports on Metal (`dm/gfx/vk/hle_vk.m`, Hades). Its shaders are the game's SPIR-V files, translated by `dm/gfx/tools/vk_shaders.py <RomFS> <shader dir> [--ios <dir>]` into `<dir>/vk/`; `build_ipa.sh` then ships `$MSL_IOS/vk` instead of the NVN chain libraries, and the NVN shader tables stay empty |
| `mem_reserve`, `mem_alias`, `mem_stack`, `app_pool` | Guest address-space partition and application pool (`hle_svc.c`) |
| `mem_used` | Memory `GetInfo(UsedMemorySize)` reports beside the heap (default `0x4000000`, 64 MB). `SetHeapSize` checks a request against the real size of the loaded modules, so a game that sizes its heap as total − used and has more than 64 MB of modules needs at least their size here. Hyrule Warriors: Age of Calamity: 66.6 MB of modules, so the default made `SetHeapSize(pool − 64 MB)` fail and `nnMain` return at once; it sets 72 MB |


**The application pool is shared by the heap and the mapped alias pages.** `dm/host/membudget.c` keeps one number:
`used = fixed used (the profile's mem_used + module bss) + heap + the unique alias pages MapPhysicalMemory has mapped`.
Each operation (map, unmap, SetHeapSize) is **one transaction**: the range check, the new-page count, the pool
comparison, the actual `mprotect` and the commit of the bitmap and counters all run under one lock, so the accounting
and the real page permissions can never be left disagreeing by two threads, and a failed effect commits nothing.
The heap log's "did it grow" test reads the transaction's own `heap_before`/`heap_after` snapshot, not the total
used memory. The heap effect is told the old size **from that lock** (`dm/host/membudget_vm.c`), not from a caller-visible copy,
so a grow that a shrink follows cannot leave the released tail pages writable. There is no separate heap-size
shadow: the transaction is the only authority, and `dm_guest_heap_readable`, `QueryMemory` and the heap log all read
the same snapshot.
Only pages that were not already mapped are charged; a map of already-mapped pages succeeds even at a full pool; an
unmap releases only pages it cleared and never goes negative. `GetInfo(UsedMemorySize)` reports the same sum the pool
check uses.

Ranges are validated by subtraction (`off <= cap`, `size <= cap - off`, non-empty, page-aligned), so no `off + size`
can wrap; an invalid range is `ResultInvalidAddress` (`0xD401`), a pool refusal is `ResultLimitReached` (`0x10801`) and
the two are not conflated. `SetHeapSize` keeps the module-image lower bound `size + image_bytes() <= app_pool` as a
separate check, and a failed heap `mprotect` leaves the heap where it was and returns an error instead of reporting
success. `mem_used` itself remains the profile's approximation and was not changed for other titles.

This follows the Horizon kernel's own rule (MapPhysicalMemory reserves `size - already_mapped` from the process's
physical-memory limit and fails with `ResultLimitReached`) rather than treating the alias region as free.

The translator (`dmsh_xlate/Program.cs`) still has Mario's texture / sampler bases and the depth convention built in. It uses the bases only to look up per-slot texture / image types in `shader_facts.tsv`; `dmsh_build.py` decodes the bindings from the profile. So a profile with other bases (Engage: `0x168` / `0x568`) builds as long as its facts table has no per-slot texture / image entries; otherwise `dmsh_build.py` stops, and the translator must take the bases from the profile first.

## Adding a game

1. **Survey.** Run `scripts/build_ipa_from_nsp.py` on the game's NSP folder. Without a profile it extracts only the code modules and a RomFS list, then writes `<NSP folder>/<title ID>_survey/survey.md`. The survey covers modules and build IDs, SDK, engine and graphics API markers, RomFS containers, the rewrite-site census, and imports compared with the host hooks.
   Unless told `--survey-only`, the script then writes a **provisional profile** to `<NSP folder>/<title ID>_build/profile/<title ID>/` (outside the repository) and carries on to a best-effort IPA. `dm/games/profile_guess.py` fills its `game.tsv` from the game files, each key under the reason for it (the survey lists them too):
   - identity and name, the build row it found, the largest RomFS file as `romfs_marker`, big file types in `zip_store`, `shader_groups` by RomFS top-level folder, Mario's NVN values (Engage's texture base under Unity IL2CPP);
   - `graphics vulkan` when `main` imports Vulkan functions and not `nvnBootstrapLoader`, then `shader_vk_capture on` when the RomFS has no SPIR-V file;
   - `modules`: a subsdk is loaded only when `main` imports something from it that the host does not supply itself. Under the Vulkan layer NVIDIA's OpenGL / Vulkan drivers, the Vulkan loader and GLSLC are dropped; movie modules and a GLSLC that `main` calls stay;
   - `shader_main_glslc` and `shader_separable` when `main` holds GLSLC outputs and the RomFS has no BNSH / BAHS / UnityFS; `shader_glslc_capture` when `main` also holds GLSL sources and calls `glslcCompile` in a module the game ships;
   - the memory partition. Without a system resource in the NPDM: the 4 GB layout, its heap region the pool − 64 MB − the bss of giant modules (Metroid Dread: 0x90000000). When `main` never sets a heap: a 1 GB block (Super Mario Galaxy). With a system resource and a heap: Engage's 5 GB block with the hardware pool, which the probe corrects;
   - SDK 8 / 10 NVN games: `shared_font ttf` and `device_api 53.313`. Engine presets: Hagi (`hagi.config`) gets `op_mode handheld` and `pad_layout full`.

   `python3 dm/games/profile_guess.py --check` runs these rules on every profile in `dm/games` (with the extractions under `/path/to/external-drive/nsp`) and lists the keys where the guess differs.

   After the rewrite, `mem_used` is set when the rewritten modules exceed the default 64 MB (a game without a system resource). A game with a system resource that sets a heap then gets a **heap check**: it boots in the Mac host (headless, no shader libraries) until its first heap request, or 5 s into `nnMain` without one, at most 30 s (`HEAP_CHECK_SECS`). A request the heap region cannot hold (`SetHeapSize OOM`) sets the alias / heap split (Tears of the Kingdom asks for 0x86000000, which gives its hand-made 0x98000000 alias region; Wonder's 1.44 GB gives 0xc0000000), and a pool check that fails for good sets `mem_used`. The profile gets a `# heap check:` line, and later runs keep its keys (delete the line to check again; `--no-heap-check` / `HEAP_CHECK = False` skips it). Other games skip the check, so it costs nothing for them and a few seconds plus a Mac host build for the rest.

   No short run decides `render_cond`, `tex_flush_upload`, `tex_dirty_upload`, `core_preempt`, `gpu_timestamps`, `feedback_snap`, `alpha_from_red` or `present_interval`, nor `op_mode` / `pad_layout` outside the presets: they keep their defaults for a developer. A minute's boot without input counted Wonder's clears under render conditions (65,536 or more; it needs no `render_cond`) as readily as Tears of the Kingdom's, saw Breath of the Wild flush 32 CPU-filled textures with data (it needs no `tex_flush_upload`) and Age of Calamity none (its movie frames come later), and Metroid Dread's movie crash shows in about half the runs. On the iPhone, `Documents/env.txt` can still set `DM_OPMODE`, `DM_NVN_GPU_TS` and `DM_NVN_FB_SNAP`, and the pad layout switches in game.

   The shader tables, `dmsh_chain.h` and `c1_full.tsv` are written into the same folder. A second run reuses that `game.tsv` (delete it to survey again), so it can be edited by hand. `--provisional` builds from a provisional profile even for a game that has one in `dm/games`, to test the guesses: `DM_GAMES_FIRST=1` makes every tool search `DM_GAMES_DIR` first, and the IPA gets `-provisional` in its name. Tools find profiles outside `dm/games` through `DM_GAMES_DIR` (folders separated by `:`, searched after `dm/games`); `make -C dm/host` reaches such a profile through the symlink `dm/host/gen/<id>/profile`. To keep a game, move the folder into `dm/games/` and bring it up as below.
2. **Profile.** Copy `010015100B514000/game.tsv` (or the provisional profile) to `dm/games/<title ID>/game.tsv` (the base game's title ID, as the folder name) and fill in the identity, `build` rows and `modules`. Leave the memory and NVN values as Mario's until the bring-up measures them ([docs/agents](../../docs/agents/README.md)).
3. **Shader tables.** Run `DM_GAME=<id> shader_split.py … dm/games/<id>/shader_map.tsv dm/games/<id>/shader_facts.tsv dm/games/<id>/shader_pairs.tsv`. Add an empty `shader_map.tsv.conflicts.tsv`, `bf_want.tsv` and `pso_manifest.tsv` (copy Mario's headers).
4. **Chain.**
   1. `DM_GAME=<id> dmsh_chain.py --header`
   2. `DM_GAME=<id> [IOSOUT=…] dmsh_build.py <pkg> <cache>`
   3. `c1_guard.py <cache>/b-<V> dm/games/<id>/c1_full.tsv`
5. **Host bring-up.** Run `make -C dm/host GAME=<id>`, then work through the bring-up loop in docs/agents. Code that only fits one game is gated by its build ID (`dm_main_build()`), never left to run on every game.
6. **IPA.** Use `GAME=<id> dm/ios/tools/build_ipa.sh`, or the NSP script, which now finds the profile.
